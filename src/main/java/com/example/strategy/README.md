# 전략 패턴(Strategy Pattern)

----

## 전략패턴 이란?
전략 패턴은 실행(런타임) 중에 알고리즘 전략을 선택하여 객체 동작을 실시간으로 바뀌도록 할 수 있게 하는 행위 디자인 패턴 이다.
여기서 '전략'이란 일종의 알고리즘이 될 수 도 있으며, 기능이나 동작이 될 수도 있는 특정한 목표를 수행하기 위한 행동 계획을 말한다.
즉, 어떤 일을 수행하는 알고리즘이 여러가지 일때, 동작들을 미리 전략으로 정의함으로써 손쉽게 전략을 교체할 수 있는, 알고리즘 변형이 빈번하게 필요한 경우에 적합한 패턴이다.

## 전략패턴 구조
![strategy.png](..%2F..%2F..%2F..%2F..%2F..%2Fdocs%2Fstrategy.png)

1. **ConcreateStrategy**: 알고리즘, 행위, 동작을 객체로 정의한 구현체
2. **Strategy**: 모든 전략 구현체에 대한 공용 인터페이스
3. **Context**: 알고리즘을 실행해야 할 때마다 해당 알고리즘과 연결된 전략 객체의 메소드를 호출
4. **Client**: 특정 전략 객체를 컨텍스트에 전달 함으로써 전략을 등록하거나 변경

## 시퀀스 다이어그램
동작 flow 는 다음과 같아요
![strategy-pattern.png](..%2F..%2F..%2F..%2F..%2F..%2Fdocs%2Fstrategy-pattern.png)

1. 동일 계열의 알고리즘군을 정의하고 → 전략 구현체로 정의
2. 각각의 알고리즘을 캡슐화하여 → 인터페이스로 추상화
3. 이들을 상호 교환이 가능하도록 만든다. → 합성(composition)으로 구성
4. 알고리즘을 사용하는 클라이언트와 상관없이 독립적으로 → 컨텍스트 객체 수정 없이
5. 알고리즘을 다양하게 변경할 수 있게 한다. → 메소드를 통해 전략 객체를 실시간으로 변경함으로써 전략을 변경

## 전략 패턴 vs 템플릿 메소드 패턴

전략 패턴과 템플릿 메소드 패턴은 모두 알고리즘을 관리하고 다양한 동작을 구현하기 위해 사용하는 디자인 패턴이지만, **알고리즘의 변경 방식과 상속 여부**에서 중요한 차이점이 있습니다.

| 특성                      | 전략 패턴 (Strategy Pattern)                             | 템플릿 메소드 패턴 (Template Method Pattern)                                                                     |
|--------------------------|------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| **목적**                   | 알고리즘을 **인터페이스로 추상화**하여 동적으로 교체할 수 있게 함               | 알고리즘의 기본 구조를 정의하고, 하위 클래스에서 세부 동작을 오버라이드하여 다양하게 구현할 수 있도록 함                |
| **구성 방식**              | 합성(Composition)을 통해 전략을 주입받고 실행 중에 전략을 교체            | 상속(Inheritance)을 통해 알고리즘을 재정의하고 변형                                                              |
| **유연성**                 | 실행 중에 전략을 변경할 수 있어 높은 유연성을 제공                        | 알고리즘의 큰 구조를 변경하기 어렵고, 서브클래스에서 세부 단계만 오버라이드 가능                                     |
| **적용 사례**              | 결제 방식 선택, 무기 시스템, 정렬 방식 선택 등 다양한 전략을 동적으로 교체가 필요한 경우 | 데이터 파싱, 프로세스 단계별 순서가 중요한 경우, 동일한 단계 내에서 다양한 구현이 필요한 경우                          |
| **알고리즘 제어 권한**      | 클라이언트가 전략 객체를 선택하고 주입하므로, **클라이언트가 제어권을 가짐**         | 템플릿 메소드가 상위 클래스에 정의되며, **상위 클래스가 알고리즘의 흐름을 제어**함                                   |
| **예제**                   | 무기 시스템에서 총, 칼, 활 등의 무기 전략을 선택하여 동작을 변경               | 파일 파싱에서 CSV, JSON 등 다양한 파일 형식에 대해 단계별로 읽고 파싱하는 구조를 상위 클래스에서 정의, 하위 클래스에서 세부 구현 |

### 패턴의 특징 및 장단점

#### 전략 패턴의 특징 및 장단점
- **특징**: 알고리즘을 독립적인 객체로 분리하여, 실행 중에 전략을 교체할 수 있습니다.
- **장점**: 동작의 유연성과 확장성이 높고, 전략 추가가 용이합니다.
- **단점**: 알고리즘마다 새로운 클래스를 만들어야 하므로 클래스 수가 많아질 수 있습니다.

#### 템플릿 메소드 패턴의 특징 및 장단점
- **특징**: 상위 클래스에 알고리즘의 골격을 정의하고, 하위 클래스에서 세부 구현을 제공합니다.
- **장점**: 공통된 알고리즘 구조를 유지하면서 세부 동작을 다양하게 구현할 수 있습니다.
- **단점**: 상속을 사용하므로 알고리즘의 큰 구조를 변경하기 어렵고, 전략처럼 동적으로 교체할 수 없습니다.
